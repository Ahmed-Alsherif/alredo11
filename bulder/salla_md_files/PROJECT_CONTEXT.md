# سلة — Salla Waste Management System

## نظرة عامة على المشروع

سلة هو نظام متكامل لإدارة خدمات جمع النفايات والاشتراكات والتحصيل الميداني والتتبع الجغرافي والإشعارات وإعادة التدوير والتقارير.

يهدف النظام إلى تنظيم العلاقة بين الإدارة والمشتركين والسائقين والمندوبين والمحاسبين، مع توفير لوحة تحكم إدارية وتطبيق جوال ميداني.

## المنصات الرئيسية

| المنصة | التقنية | الوصف |
|---|---|---|
| Backend | Django REST Framework + Python | خادم الـ API المركزي لقواعد العمل والبيانات |
| قاعدة البيانات | MySQL | مصدر البيانات الدائم |
| لوحة الإدارة (Dashboard) | Next.js + TypeScript + Tailwind CSS + React | واجهة الإدارة والمحاسبة عبر المتصفح |
| تطبيق الجوال (Mobile) | Expo + React Native + Expo Router | تطبيق ميداني للمشترك والسائق والمندوب |

### ملاحظات تقنية

- المصادقة: JWT عبر `djangorestframework-simplejwt` — يحصل المستخدم على `access` و `refresh` token عند تسجيل الدخول.
- التوجيه في الجوال: يستخدم Expo Router (file-based routing) مع مجلدات مفصولة لكل دور: `(agent)`, `(driver)`, `(subscriber)`.
- CORS: مفعّل للسماح بالاتصال بين الـ Dashboard (منفذ 3000) والموبايل (Expo) والـ Backend (منفذ 8000).
- الملفات والصور: تُخزن في `MEDIA_ROOT` وتُقدّم عبر Django في بيئة التطوير.

## أدوار المستخدمين

| الدور | المنصة | الوصف |
|---|---|---|
| Admin (مدير/أدمن) | Dashboard | إدارة كاملة: موظفين، مشتركين، مناطق، مسارات، شكاوى، تقارير |
| Accountant (محاسب) | Dashboard | الشؤون المالية: مطابقة العهد، المصروفات، الجزاءات، السلف، التقارير المالية |
| Driver (سائق) | Mobile | العمل الميداني: مسار اليوم، تتبع الشاحنة، البلاغات، تأكيد إعادة التدوير |
| Agent (مندوب) | Mobile | التحصيل الميداني: تسجيل مشتركين، التحصيل النقدي، تسليم العهدة، متابعة المتأخرين |
| Subscriber (مشترك) | Mobile | المشترك: الاشتراك، تتبع الشاحنة، الشكاوى، إعادة التدوير، التقييم |

### ملاحظات على الأدوار

- لا توجد شاشة اختيار دور — بعد تسجيل الدخول، يوجّه النظام المستخدم تلقائياً لواجهته بناءً على `user.role`.
- المشترك هو الدور الوحيد المسموح له بالتسجيل الذاتي.
- باقي الأدوار (سائق، مندوب، محاسب، أدمن) تُنشأ من قبل الإدارة فقط.
- الأدمن (Admin) هو نفسه المدير — لا يوجد دور "Manager" منفصل.

## الوحدات الرئيسية

| الوحدة | Django App | الوصف |
|---|---|---|
| الحسابات والمصادقة | `accounts` | تسجيل الدخول، إدارة المستخدمين والموظفين، وثائق الموظفين |
| المناطق والمسارات | `zones` | المناطق الجغرافية، قوالب المسارات، أيام الجمع |
| المشتركون والاشتراكات | `subscribers` | المشتركين، خطط الاشتراك، سجل الاشتراكات |
| التتبع الجغرافي | `tracking` | مواقع الشاحنات، زيارات الجمع اليومية |
| الإشعارات | `notifications` | مركز الإشعارات الداخلي |
| الشكاوى والجودة | `complaints` | شكاوى المشتركين، البلاغات الميدانية، تقييم الخدمة |
| إعادة التدوير | `recycling` | طلبات إعادة التدوير، النقاط، المكافآت |
| الشؤون المالية | `finance` | المدفوعات، المصروفات، تسليم العهدة، الجزاءات، السلف، المكافآت |
| التقارير | `reports` | لوحة المؤشرات، التقارير المالية والتشغيلية، التصدير |

## منهجية التطوير

- يتم تنفيذ المشروع على مراحل حسب ملف `DEVELOPMENT_PLAN.md`.
- كل مرحلة يتم اختبارها قبل الانتقال للمرحلة التالية.
- مجلد `docs/` يوثّق ما تم بناؤه فعلياً في النظام الحالي.
- مجلد `salla_md_files/` هو المرجع النهائي للنظام المكتمل الذي نسعى لتحقيقه.
