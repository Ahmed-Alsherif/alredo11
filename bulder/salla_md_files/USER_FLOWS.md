# User Flows

## Scope

هذا الملف يصف تدفقات المستخدم الفعلية المبنية على النظام الحالي مع الإضافات المخططة.
التدفقات المخططة مميزة بعلامة `[مخطط]`.

---

## تدفق المصادقة العام

ينطبق على جميع الأدوار.

1. المستخدم يفتح التطبيق أو الـ Dashboard.
2. يدخل اسم المستخدم وكلمة المرور.
3. Backend يتحقق من البيانات عبر JWT.
4. Backend يعيد: `access` token + `refresh` token + `role`.
5. النظام يوجّه المستخدم تلقائياً للواجهة المناسبة بناءً على `role`.
6. المستخدم يرى فقط شاشات وإجراءات دوره.

قواعد:

- لا تظهر شاشة اختيار الدور — التوجيه تلقائي.
- المشترك فقط يستطيع التسجيل الذاتي.
- باقي الأدوار تُنشأ من قبل الإدارة.

المتطلبات: STF-05, STF-06, STF-07.

## تدفقات المشترك

### 1. التسجيل الذاتي

1. المشترك يفتح شاشة التسجيل من صفحة الدخول.
2. يدخل: الاسم، الهاتف، البريد، كلمة المرور.
3. Backend ينشئ `User(role=subscriber)` + `Subscriber`.
4. يتم توليد `subscription_id` فريد (SUB-XXXX).
5. المشترك يسجل الدخول ويرى الصفحة الرئيسية.

المتطلبات: SUB-01, SUB-07, STF-05.

### 2. الصفحة الرئيسية وأيام الجمع

1. المشترك يسجل الدخول.
2. تظهر حالة الاشتراك (اللون: أخضر/أصفر/أحمر).
3. تظهر أيام الجمع من المسار المرتبط.
4. تظهر اختصارات سريعة للأقسام.

المتطلبات: SUB-03, SUB-10, NOT-05.

### 3. إدارة الاشتراك

1. المشترك يفتح شاشة الاشتراك.
2. يرى الباقة الحالية وتواريخ البداية/النهاية.
3. يمكنه عرض الباقات المتاحة.
4. يمكنه تجديد أو إلغاء الاشتراك.

المتطلبات: SUB-02, NOT-03.

### 4. الإيقاف المؤقت

1. المشترك يضغط زر الإيقاف المؤقت في شاشة الاشتراك.
2. النظام يسجل `is_paused=True` و `paused_at`.
3. عند الاستئناف: يمدّد `subscription_end` بعدد أيام الإيقاف تلقائياً.

المتطلبات: SUB-09.

### 5. تتبع الشاحنة

1. المشترك يفتح شاشة التتبع.
2. النظام يتحقق من الشاحنة المعيّنة لمسار المشترك.
3. عند الاقتراب، يظهر موقع الشاحنة على الخريطة.

المتطلبات: GEO-03.

### 6. الشكاوى وتقييم الخدمة

1. المشترك يفتح شاشة الشكاوى.
2. يقدم شكوى نصية أو مصورة (late/damaged/missing/other).
3. يتابع حالة شكاواه السابقة.
4. يمكنه تقديم تقييم شهري للخدمة (1-5 نجوم).

المتطلبات: QC-01, QC-02, QC-04.

### 7. إعادة التدوير

1. المشترك يطلع على فئات الفرز في شاشة التوعية.
2. يفتح شاشة إعادة التدوير → يحدد الفئة وعدد الأكياس.
3. يرسل الطلب → يظهر بحالة `pending`.
4. بعد تأكيد السائق → تُمنح النقاط تلقائياً.
5. يرى ترتيبه في لوحة المتصدرين.

المتطلبات: REC-01 إلى REC-06.

### 8. استلام إيصال الدفع

1. المندوب يحصّل المبلغ ميدانياً.
2. النظام ينشئ إيصال رقمي (`REC-XXXXXX`).
3. المشترك يستلم إشعار الإيصال.

المتطلبات: FIN-01, NOT-04.

## تدفقات السائق

### 1. مسار اليوم

1. السائق يسجل الدخول.
2. التطبيق يوجّهه لواجهة السائق.
3. يرى المسار النشط لليوم ضمن منطقته.
4. يرى قائمة المشتركين المجدولين مع إمكانية البحث والفرز.
5. يحدّث حالة كل زيارة (collected/skipped/issue).

المتطلبات: OP-09, OP-13, GEO-04.

### 2. تحديث موقع الشاحنة

1. السائق يبدأ العمل الميداني.
2. التطبيق يرسل تحديثات GPS بشكل مستمر.
3. Backend يخزن المواقع في `TruckLocation`.
4. الأدمن يراقب الشاحنة على الخريطة المباشرة.
5. المشترك يرى الشاحنة عند الاقتراب.

المتطلبات: GEO-01, GEO-02, GEO-03.

### 3. التنقل للمشترك

1. السائق يفتح مشترك من القائمة أو من Pin على الخريطة.
2. يظهر موقع المشترك ومسار الوصول.

المتطلبات: GEO-05.

### 4. البلاغ الميداني

1. السائق يجد حالة سلة استثنائية.
2. يفتح شاشة البلاغ → يحدد النوع (full/damaged/missing/empty).
3. يرفق صورة ويكتب ملاحظة.
4. النظام يحفظ البلاغ ويرسل إشعار.

المتطلبات: QC-03, NOT-02.

### 5. تأكيد إعادة التدوير

1. السائق يرى طلبات إعادة التدوير ضمن دورته.
2. يؤكد استلام الأكياس المفرزة.
3. النظام يمنح النقاط تلقائياً.

المتطلبات: REC-03, REC-04.

## تدفقات المندوب

### 1. تسجيل مشترك ميدانياً

1. المندوب يفتح شاشة التسجيل.
2. التطبيق يحاول التقاط GPS تلقائياً.
3. المندوب يدخل بيانات المشترك.
4. يختار باقة اشتراك (محمّلة ديناميكياً من `/api/plans/`).
5. **GPS Fallback**: إذا لم يُلتقط الموقع → ربط بمنطقة المندوب (`profile_zone`).
6. Backend ينشئ `User` + `Subscriber` + يولّد `subscription_id`.
7. **يتم استدعاء `update_color_status()`** → المشترك يظهر بالأحمر (مستحق الدفع).

المتطلبات: SUB-01, SUB-04, SUB-05, SUB-07, SUB-12, OP-11, OP-12.

### 2. عرض المشتركين

1. المندوب يفتح شاشة المشتركين.
2. يرى **أزرار تصفية سريعة (Filter Chips)**: الكل، غير المسددين، المسددين — مع أعداد ديناميكية.
3. كل بطاقة مشترك تعرض: الاسم، الباقة، المبلغ المستحق، شارة اللون.
4. يمكنه البحث والفرز.

المتطلبات: SUB-06, OP-14, SUB-10.

### 3. التحصيل النقدي الميداني

1. المندوب يفتح شاشة التحصيل.
2. **يبحث عن المشترك** بالاسم أو الهاتف أو الرقم (بحث ذكي مع قائمة منسدلة).
3. عند الاختيار → **يتعبأ حقل المبلغ بالرصيد المستحق تلقائياً**.
4. المندوب يؤكد → Backend ينشئ `Payment` + يولّد `receipt_number`.
5. `Payment.save()` يستدعي `subscriber.update_color_status()`.
6. يتم إنشاء `SubscriptionLog` مع تمديد `subscription_end`.
7. الدفعة تظهر بحالة "قيد الإيداع" (`pending`).
8. يتم إرسال إشعار إيصال للمشترك.

المتطلبات: FIN-01, NOT-04, FIN-02.

### 4. تسليم العهدة النقدية

1. **بنر تنبيهي** يظهر أعلى شاشة التحصيل عند وجود مبالغ معلقة.
2. البنر يعرض: عدد العمليات المعلقة + المبلغ الإجمالي + زر "تسليم للمحاسب".
3. المندوب ينقر الزر → يُطالب بالتأكيد.
4. عند الموافقة → Backend ينشئ `CollectionSettlement(status=pending)`.
5. جميع الدفعات المعلقة ترتبط بالمحضر (`Payment.settlement_id`).
6. حالة الدفعات تتحول إلى `deposited`.
7. البنر يختفي بعد التسليم.

المتطلبات: FIN-02.

### 5. تحديث بيانات المشترك

1. المندوب يفتح تفاصيل المشترك.
2. يحدّث بيانات الاتصال أو الموقع.
3. إذا تغيّر الموقع → Backend يتحقق من التغطية.
4. يُحفظ التحديث إذا كان ضمن التغطية.

المتطلبات: SUB-08, SUB-05.

## تدفقات المحاسب

### 1. مطابقة العهدة

1. المحاسب يسجل الدخول في Dashboard.
2. يفتح شاشة تسليم العهدة (`Settlements`).
3. يرى محاضر التسليم المعلقة من المناديب.
4. يراجع المبلغ والدفعات المرتبطة.
5. يوافق أو يرفض المحضر.
6. عند الموافقة → حالة المحضر تصبح `approved`.

المتطلبات: FIN-02.

### 2. تسجيل المصروفات

1. المحاسب يفتح شاشة المالية.
2. يسجل مصروف جديد: الوصف، المبلغ، الفئة (وقود/صيانة/رواتب/تسويق/أخرى).
3. المصروف يظهر في التقارير المالية.

المتطلبات: FIN-03, REP-03.

### 3. الجزاءات والسلف

1. المحاسب يسجل جزاء مالي: الموظف، السبب، المبلغ.
2. المحاسب يسجل سلفة: الموظف، المبلغ، الملاحظة.
3. يحدّث حالة السلفة (active/paid).

المتطلبات: FIN-05, FIN-06.

### 4. التقارير المالية

1. المحاسب يفتح شاشة التقارير.
2. يرى: إيرادات شهرية، مصروفات شهرية، عدد المدينين.
3. يمكنه تصدير التقرير كـ PDF أو Excel.

المتطلبات: REP-03, REP-05.

## تدفقات الأدمن

### 1. إدارة الموظفين والحسابات

1. الأدمن يسجل الدخول في Dashboard.
2. يفتح شاشة الموظفين.
3. ينشئ سجل موظف + حساب دخول (يحدد الدور: driver/agent/accountant).
4. يرفع وثائق الموظف (هوية، رخصة، عقد).
5. يمكنه تعديل البيانات أو إعادة تعيين كلمة المرور.
6. يمكنه حذف الموظف.

المتطلبات: STF-01 إلى STF-07.

### 2. إدارة المناطق والمسارات

1. الأدمن يفتح شاشة المناطق.
2. ينشئ منطقة جديدة (اسم + حدود).
3. يفتح شاشة المسارات → ينشئ مسار ويربطه بمنطقة وسائق وأيام جمع.
4. يمكنه تعديل أو حذف أو تجميد المسار.

المتطلبات: OP-01 إلى OP-10.

### 3. إدارة المشتركين

1. الأدمن يفتح شاشة المشتركين.
2. يبحث ويفلتر بالمنطقة أو اللون أو الحالة.
3. يرى تفاصيل المشترك: البيانات، الاشتراك، السجل المالي.
4. يمكنه أرشفة الحسابات القديمة.

المتطلبات: SUB-06, SUB-08, SUB-11.

### 4. متابعة الشكاوى

1. الأدمن يفتح شاشة الشكاوى.
2. يراجع الشكاوى الجديدة.
3. يحدّث الحالة (new → in_progress → resolved).

المتطلبات: QC-02.

### 5. التقارير

1. الأدمن يفتح شاشة التقارير.
2. يرى: لوحة مؤشرات + تقارير مالية + تشغيلية + نمو.
3. يمكنه تصدير أي تقرير كـ PDF أو Excel أو CSV.

المتطلبات: REP-01 إلى REP-05.
